# Article template revision verification

## Automated tests

The complete project suite passed **60 tests** (`python -m pytest -q -p no:cacheprovider`; 23 September 2026). Tests cover article template versioning/activation, independent journals, Super Admin/Journal Admin access, Finance and cross-journal denial, profile extraction, page/font/margin fixes, missing sections, abstract/keyword rules, DOCX package preservation, protected number changes, report XLSX, PostgreSQL table compilation, the guided review workflow, and the default one-click `Auto Format & Generate` workflow. The fast-mode regressions prove that all deterministic safe fixes are applied without individual approval, non-blocking warnings do not prevent DOCX/XLSX creation, low-risk batch decisions survive the automatic re-audit, the master header/footer is populated, integrity checks pass, and the original manuscript remains byte-identical. Dedicated protected-caption fixtures include both bookmarks and native Word fields: compliant notation is `COMPLIANT_PROTECTED`, non-compliant notation is `WARNING_PRESERVED`, both caption subtrees remain unchanged, generation succeeds, and the XLSX records object type and preservation reason. ELKOLIND tests also cover explicit margin confirmation in the Streamlit UI, DOI-suffix fallback, four-word title logic, body date placeholders, independent first/even/default headers and footers, native PAGE fields, barcode image relationship copying, metadata correction/template reselection audit, scientific-content integrity, and complete-XML placeholder detection in DrawingML/VML textboxes with placeholders split across Word runs. Existing JAS tests continued to pass.

## DOCX regression

`scripts/generate_article_revision_demo.py` applied 28 safe format fixes to the existing multi-page representative DOCX and generated a non-official master, formatted DOCX, and XLSX compliance report under `samples/article_revision/`. Structural checks passed: text, numbers, citations, DOI, all package parts outside `word/document.xml`, header/footer XML, embedded media, table text, Word equation XML, drawings, references, and section breaks were unchanged.

The packaged LibreOffice renderer could not run because `soffice.exe` was unavailable. The same source and formatted DOCX files were therefore rendered through the application's Microsoft Word conversion strategy in an authorized desktop session. Both produced **two pages**. Every page image was inspected: header/footer remain visible on both pages; title, headings, body text, table, figure caption, equation, and reference block remain; the intended typography and margin changes are visible; no clipping or overlap was observed. The figure embedded in this existing representative fixture is a one-pixel placeholder, so visual appearance of a substantial image cannot be judged from this fixture; binary media/drawing preservation is covered structurally.

The LoA masters are not article templates. A previously uploaded ELKOLIND Article Master was available through the existing private revision storage and was used read-only for the textbox regression below. A compact test fixture removes embedded font binaries but retains the relevant official header/textbox, PAGE-field, media, and relationship structures. A JASENS Article Master was not available for equivalent visual acceptance. Demo files must not be represented as official journal templates.

## ELKOLIND header/footer regression

A synthetic template-compatible ELKOLIND master was used with the existing multi-page manuscript fixture. It is **not** the official article master and its embedded image is a one-pixel placeholder, not a replica of the official barcode. The deterministic formatter applied 30 safe formatting fixes; the page-furniture graft replaced 17 metadata tokens and copied seven master parts, including one image relationship. The resulting DOCX passed the body-text, table/figure/equation, original-part, odd/even, and native-PAGE integrity checks.

The packaged renderer could not find `soffice.exe`, so the generated DOCX was converted by the application's Microsoft Word strategy. A forced third page was added to exercise every Word page variant. Intermediate renders exposed a PAGE number touching the ISSN, a missing default header on page 3 when master references were reordered, and a missing even header when `w:titlePg` was inserted after `w:docGrid`. The DOI spacing, PAGE fallback, master reference order, and schema-valid `w:titlePg` placement were corrected and locked into automated assertions.

All **three final page images were rerendered and inspected**. The journal header and DOI are visible on the first, even, and odd/default pages; page 1 has the first-page ISSN footer, page 2 has the distinct first-author/four-word-title even footer, page 3 has the odd/default ISSN footer, and native PAGE fields render 1, 2, and 3. No clipping or missing scientific text was seen in this synthetic test. Official logo/barcode placement and exact ELKOLIND typography cannot be certified without the real article DOCX.

## ELKOLIND textbox placeholder regression

The validator now reads every `w:t` node from each referenced default, first, and even header/footer XML part. It does not depend on `python-docx` paragraph enumeration. Regression coverage uses Word-generated DrawingML shapes with VML fallbacks, a footer textbox, duplicated alternate-content branches, and an additional variant where placeholders are split across adjacent runs. Both `{{doi_full}}` and the official `10.33795/elkolind.v{{volume}}i{{issue}}.{{doi_suffix}}` construction are accepted; a bare suffix without the ELKOLIND DOI prefix is not treated as configured.

The full Quick Template Revision service test uploaded the textbox master, audited and approved safe fixes, generated the final DOCX, and verified that all placeholders were populated. Native PAGE fields, DrawingML/VML textbox structures, barcode/media bytes, and relationship parts remained present. The final generated DOCX was copied to a short QA path to avoid Microsoft Word's legacy path-length limitation, converted successfully, and visually inspected. The header, DOI, page number, scientific body, footer ISSN, and barcode were visible with no flattening or unexpected content change.
